TRADE-OFFS & GOALS · FOR DEVELOPERS

取舍笔记

做产品不是选「最好的方案」，而是在约束里选「最合适的方案」。 这一页公开错题局的全部重大取舍：现在的目标、未来的目标、放弃了什么、每一个决定背后的为什么。 所有「未拍板」也都如实标注——诚实比好看重要。

🎯 目标坐标

先搞清楚「现在要去哪」，才能理解每个取舍为什么合理。

现在：验证一个闭环

  • 用约 50 人私测验证核心闭环：拍照录题 → 错题卡 → 记下错因 → 按结果调度复习
  • 验证「讲给小菊听」的语音复习链路是否真的可行
  • 用真实题目、真实口述、真实失败率，算出「可靠完成一次复习」的成本
  • 不追求注册量——优先指标是持续使用、复习完成、错题减少

「个人声誉与下一阶段机会 > 真实高中生使用与自身学习；收入守住不长期亏损底线。」—— 12 个月成功定义

未来：从收件箱到掌握系统

  • 近期：题型标签、考前突击、批量录入、照片标记提取
  • 中期：FSRS 智能调度（替代固定间隔）、辨识题/变式题链路
  • 中期：互惠制社区——共享换访问，但永远不是排行榜
  • 远期：数据主权完全体——MCP 适配层 + 全量导出，用户带着自己的 AI 来用
  • 愿景：错题减少 → 学习复盘 → 掌握系统，帮学生减少应试的重复耗时

「最难复制的不是某个 OCR 或大模型 API，而是高中生日常现场的高频反馈循环。」—— 创始人本人就是在校高中生

📏 决策纪律

所有取舍都遵守的四条元规则。

RULE 01

先证明产品价值，再定义学习系统，再确定可持续边界，最后固化运营基础。跳过前一层直接选框架和模型，技术选择就建立在未确认的假设上。

RULE 02

每一个「延后」都必须写下重新评估的触发条件。没有触发条件的「以后再说」，就是逃避决策。

RULE 03

旧决策文档原位保留、不静默改写。方向反转时用新 ADR 说明取代关系——决策的历史本身就是资产。

RULE 04

选型标准是「可靠完成一次任务的总成本」（含失败、重试、人工纠错），不是 Token 单价，更不是厂商榜单。

⚖️ 取舍墙

十个重大决策：选了什么、放弃了什么、什么时候会重新评估。

#01

客户端：React PWA → Flutter，方向反转

已拍板
背景

最初定了 React + Vite PWA，想「链接即达」快速验证。但第一版核心交互是拍照、连拍、持续语音——这些在移动浏览器里处处受限。

✅ 选了

Flutter + Android APK 作为第一版唯一主终端；Web 降级为静态宣传页（你正在看的这个站）。

❌ 放弃

React 生态、链接即达的分发便利、Kotlin 原生（未来 iOS 要重写）、React Native（与「不引入 Node」约束冲突）。

🔄 重评

iOS 必须由新的范围决策启动，Flutter 只保留技术可能性。

出处：adr/flutter-android-primary-client.md · 旧 React 条款原位保留在 v1-modular-monolith 中（决策纪律 RULE 03 的实例）
#02

复习调度：固定间隔 vs FSRS

已拍板
背景

FSRS 是更「先进」的间隔重复算法，但参数复杂、对学生不可解释。

✅ 选了

1·3·7·14·30 天固定间隔：做错次日再来，做对推进下一档。规则简单到能跟学生讲清楚。

❌ 放弃

FSRS 高级信号、随机复习时间、响应时长优化——不是永久放弃，是「先可解释，后升级」。代码里完成 30 天轮次的状态必须叫 sequence_completed，禁止写 mastered——「掌握」要等辨识题链路验证。

🔄 重评

原型验证后的工程化阶段，迁移字段已预留。

出处：PRODUCT-BLUEPRINT.md §2.3 / §2.10
#03

托管：官方托管 vs BYOK（自带密钥）

已拍板
背景

BYOK 能让官方现金流压力归零，是开发者工具的常见选择。

✅ 选了

官方统一托管 + Managed AI。高中生不该被要求「先去申请三个 API Key」才能开始复盘错题。

❌ 放弃

BYOK、第一天同时支持自托管——认证、配置、测试、计费、支持的复杂度远超 50 人 Demo 所需。代价是官方承担供应商费用和滥用风险。

🔄 重评

出现真实的开发者 / 学校 / 隐私需求时。

出处：adr/official-hosted-backend-managed-ai.md
#04

后端：模块化单体 vs 微服务

已拍板
背景

两段旧讨论留下了互相冲突的方案：FastAPI+PostgreSQL vs Next.js+NestJS+MySQL+Redis。

✅ 选了

FastAPI 模块化单体 + PostgreSQL + 一张 ai_jobs 表 + 单 Python Worker。4 核 4G 小服务器跑 50 人私测，够了。

❌ 放弃

NestJS 全栈 TS、Redis/BullMQ、微服务、独立 OCR 服务、Kubernetes——不为了「像大公司」而提前建设。任务表只实现状态机 + 重试 + 幂等键，防止它腐烂成自制消息队列。

🔄 重评

任务积压、并发消费、优先级被真实数据证明超出数据库方案时，新建 ADR 比较专业队列。

出处：adr/v1-modular-monolith-and-base-stack.md
#05

AI 接入：能力薄适配 vs 通用 Gateway

已拍板
背景

AI 供应商能力和价格都在快速变化，直连单一 SDK 会把替换成本焊进核心流程。

✅ 选了

按能力做薄适配层：只抽象第一版真用到的 OCR、实时语音、推理。允许保留供应商原始结果调试，但原始结果不成为权威业务状态。

❌ 放弃

第一天就建通用 AI Gateway、为 Embedding / 变式题生成预建抽象——「不为抽象而预建」。可替换不等于零成本替换。

🔄 重评

动态路由有真实需求后另立 ADR。

出处：adr/ai-capability-adapters-and-cost-aware-routing.md
#06

数据：自有底座 vs 供应商知识库

已拍板
背景

把业务数据建在 AI 供应商的知识库平台上，接入最快。

✅ 选了

业务数据完全自有，供应商只提供处理能力、只接收完成当前任务所需的数据。错题局的核心状态是用户的长期复习历史和数据边界，不是某个供应商的模型输出。

❌ 放弃

供应商知识库做主底座（复习状态、权限、分享规则难以准确表达，迁移成本极高）、全自研本地模型（算力与维护远超原型需要）。

出处：adr/self-controlled-business-data.md
#07

图片：原图保护策略

已拍板
背景

错题照片是学生的原始资产，但原图也是最占存储的东西。

✅ 选了

原图与 OCR 衍生图分开保存；用户确认前绝不丢弃原图；云存储生命周期规则被明确禁止匹配原图前缀——防止云端规则绕过用户确认。

❌ 放弃

只存黑白图省空间（可能丢失颜色、批注、图形信息）；题干不做 OCR，长期只存裁剪图——识别算力花在学生手写批注上。

🔄 重评

原图保留时长、存储额度、自动删除规则仍未定案。

出处：PRODUCT-BLUEPRINT.md §2.9 / §8.3 · v1-implementation-plan.md §5
#08

模型选型：讯飞 X2 vs DeepSeek

未拍板
背景

需要推理底座 + OCR + 实时语音。X2 胜在教育行业资产与 OCR/语音一站式；DeepSeek 胜在通用推理、开放权重、成本和超长上下文。

📋 计划

讯飞 OCR 独立做图像识别，同一份 OCR 文本同时喂给 X2 和 DeepSeek 对照：结构化准确率、标签一致性、错因质量、时延、真实成本。

⚠️ 纪律

不能仅根据厂商榜单断言谁更适合；展会展示的教育能力 ≠ 已开放、可采购、有 SLA 的接口；国外模型可作质量上限对照，但不成为未经验证的默认生产依赖。

出处：PRODUCT-BLUEPRINT.md §4.1–4.6 / §8.5
#09

收费：成本控制点放在哪

未拍板
背景

对标产品把「每月录题次数」做成付费墙——但录题是最需要培养的行为，给它设限会增加学生每次拍照的心理成本。

📋 倾向

基础录入免费或非常宽松；轻量 AI 给大额度；深度 AI（整卷结构化、错因诊断）按点数；生成类（变式题、报告）独立增值包。把成本控制点放在昂贵的 AI 动作上，而不是「保存一道错题」。

⚠️ 未决

学生还是家长付款、订阅还是点数、免费额度具体值；「核心行为免费」是否等于「无限云端调用免费」也需要拆开。

出处：PRODUCT-BLUEPRINT.md §5.2–5.4
#10

开源：AI Coding 时代的护城河

未拍板
背景

AI 让代码保密的价值下降，闭源不能作为主要护城河——那靠什么？

📋 倾向

开源方法层（数据格式、调度引擎、适配接口、评测工具）+ 官方托管应用闭源。真正难复制的是：学生长期复习数据、真题验证的错因结构、成本控制、社区网络、迭代速度。

⚠️ 纪律

不第一天承诺完整自托管——对高中生没有购买价值，只会产生安装、升级、安全和免费支持成本。对学生，开源要翻译成「数据可导出、不会被锁定」，而不是把许可证名称当卖点。

出处：PRODUCT-BLUEPRINT.md §8.7 全部子节

🗃 放弃与后置清单

每一项都附原因。标「后置」的都有明确的重新评估触发条件——不是放弃，是排队。

辨识题 / 变式题学习机制的完全体需要它，但生成、求解、校验是独立链路，初期不实现后置
FSRS 智能调度先用可解释的固定间隔验证产品，算法升级留到工程化阶段后置
iOS 端Flutter 保留技术可能，但必须由新的范围决策启动后置
Web 业务端React PWA 方案被整体放弃，Web 只留静态宣传页已放弃
实时可视化公式面板「用户说什么面板就写什么」很酷，但第一版转写只是 AI 判断的内部输入后置
社区功能互惠制原则已定，但共享字段、版权、未成年人合规全部待设计；数据库只预留 visibility 字段后置
标签体系避免标签体系先于真实数据膨胀——字段保留但留空后置
Redis / 消息队列 / 微服务数据库任务表够用就不引入专业队列，每项都有重评触发条件后置
BYOK / 自托管对高中生门槛过高，出现真实需求再评估后置
排行榜 / 个人画像 / 全科 AI 老师与产品理念直接冲突，不是排期问题，是不做已放弃
抓取第三方题库合规底线，任何时候都不做已放弃
