# 自有业务数据底座与外部 AI 能力分离

## 简要概括

错题局将用户、题目、答案、复习状态、私人备注和分享授权保存在自己控制的数据底座中。讯飞、DeepSeek 等外部 OCR、语音、知识库和模型服务只承担单次处理任务，不成为权威业务数据来源。

## 状态

已接受

## 上下文

### 要解决的问题

错题局需要长期维护可解释的复习状态、私人和公共数据边界、不可撤回的公共副本、答案版本以及用户删除请求。如果把这些状态直接放入某个模型供应商的知识库或应用平台，业务结构会被供应商能力绑定，迁移、权限控制和故障降级都会变得困难。

另一方面，OCR、实时语音和模型推理没有必要全部自研。项目需要使用外部能力，同时保留业务数据的控制权。

### 决策依据

- 用户数据、权限和复习状态是否可控；
- 能否更换 OCR、语音和模型供应商；
- 是否支持私人数据与公共题目隔离；
- 是否能完成备份、删除、导入导出和审计；
- 第一版是否仍可使用成熟外部 API 快速验证；
- 是否避免过度建设自有模型和基础设施。

### 考虑过的选项

#### 选项 A：业务数据直接建立在供应商知识库或应用平台

- 做法：把题目、答案、用户资料和检索能力集中存入单一 AI 供应商平台。
- 优点：接入快，部分检索和管理功能可以直接使用。
- 缺点：复习状态、权限和分享规则难以准确表达；迁移成本高；供应商故障会影响全部业务。
- 适用条件：短期演示、无长期用户状态的内部工具。

#### 选项 B：自有业务数据底座，供应商只提供处理能力

- 做法：业务数据存入错题局控制的数据库和对象存储；外部服务按任务接收最少数据，结果回写自有系统。
- 优点：数据、权限和迁移可控；可以替换供应商；适合长期复习状态和社区边界。
- 缺点：需要自己设计数据模型、备份、权限和任务编排。
- 适用条件：需要长期用户状态、数据互通和多供应商能力的正式产品。

#### 选项 C：第一版全部自研并本地运行 OCR、语音和模型

- 做法：业务数据和所有 AI 能力都部署在错题局服务器中。
- 优点：控制力最强，理论上减少第三方数据流转。
- 缺点：模型部署、算力、性能和维护成本远超原型需要。
- 适用条件：规模、隐私或成本已经证明本地模型更合理。

## 决策

我们将采用自有业务数据底座，并把外部 OCR、语音、知识库和模型视为可替换的处理能力，因为错题局的核心状态是用户的长期复习历史、私人数据边界和公共贡献关系，而不是某个供应商的模型输出。

业务数据库和对象存储可以使用云厂商托管产品，但账号、结构、备份和迁移权由错题局掌握。供应商只接收完成当前任务所需的数据。供应商知识库可以作为辅助检索层，但不能替代权威业务数据库。

## 后果

### 正面后果

- 用户、题目、复习和分享状态有唯一权威来源；
- 可以替换 OCR、语音和推理模型；
- 私人原图、公共清洁题目和社区贡献可以使用独立权限；
- 支持备份、导出、删除和后续跨端同步；
- 供应商故障时可以保留基础复习能力。

### 负面后果与代价

- 项目需要设计和维护数据库、对象存储、权限和备份；
- 外部任务结果需要校验、重试和记录供应商版本；
- 供应商适配仍需要开发，不可能完全零成本切换；
- 数据处理链路和隐私责任由错题局统一承担。

### 风险、缓解措施与后续验证

- 风险：为了可替换性过早建设复杂统一平台。
  - 缓解：第一版只为每类能力定义薄接口，先接入一个主供应商和一个离线评测候选。
  - 验证：确认替换候选时不需要修改错题、复习和权限数据结构。
- 风险：外部服务保留或处理超出任务所需的数据。
  - 缓解：选择中国内地服务区域，核对供应商数据条款，只发送最少必要内容。
  - 验证：上线前完成每个供应商的数据流和保存期限清单。
- 风险：自有数据底座发生丢失或权限泄漏。
  - 缓解：使用托管数据库、对象存储权限、备份和最小权限访问。
  - 验证：正式私测前完成恢复演练和私人/公共权限测试。
