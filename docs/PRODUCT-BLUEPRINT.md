## 2. 已确认的产品定义

### 2.1 定位

“错题局”主要面向高中生，针对学习复盘场景。产品不做 AI 解题助手，不与成熟搜题和解题产品正面竞争；先通过错题录入和复习调度形成简单、明确的生态位，再逐步扩展为错题减少、学习复盘和掌握系统。

相关决策：[`DEC-0008`](memory/decisions/DEC-0008-core-product-positioning-and-loop.md)。

### 2.2 核心闭环

1. 用户拍照录入一道或多道错题；
2. 系统从照片中提取题目文字；
3. 系统形成类似 Anki 的错题卡；
4. 用户添加或修改备注：当时怎么想、为什么做错、下次注意什么；
5. 复习时展示原题和上一次备注；
6. 系统根据作答结果安排下一次复习。

### 2.3 基础复习规则

复习间隔采用 1、3、7、14、30 天：

- 做错后，次日继续复习；
- 再次做错，下一天继续；
- 做对后，推进到下一个复习间隔。

后期阶段做错后的具体回退规则仍未决定。相关决策：[`DEC-0009`](memory/decisions/DEC-0009-spaced-review-rule.md)。

### 2.4 社区数据原则

用户可选择是否将自己的数据加入社区。参与共享的用户可以访问其他参与者共享的数据；不参与的用户不能访问社区共享数据。具体共享字段、版权、撤回和未成年人合规仍需设计。

相关决策：[`DEC-0010`](memory/decisions/DEC-0010-reciprocal-community-data-sharing.md)。

社区不是排行榜。它当前只确定为围绕公共题目、答案和思路展开的讨论与表达空间，具体形态仍待定义。第一版不做社区排行榜、公开比较错题数量和他人完整思路展示。

用户主动分享即授权生成不可撤回的公共副本；之后可以删除自己的私人记录，但不能撤回已经进入公共讨论区的清洁题目和贡献。清洁题目图进入公共区前必须经过用户确认，清洁失败则保留在私人区。

用户原图和公共题目首先采用严格的逻辑存储与权限隔离，初期不要求为此运行两套物理数据库。

### 2.5 第一版学科与骨架

首个 Demo 先覆盖数学、物理、化学和生物。产品骨架是“入题”和“复习”两件事。

核心学习机制：`自己的错误思路 → 原题优先 → 多轮间隔独立做对 → 仍未掌握或主动强化时做辨识题`。

“掌握”不仅是记住原题，还包括遇到相似题时能识别同一模式。每一轮都需要由用户最终确认已经独立完成才能推进；AI 只提供关键步骤检查和提示，任一轮做错则回到第一轮重新建立掌握。

### 2.6 录题与标准答案预处理

题目在录入时必须预先保存标准答案或标准过程，而不是在每次复习中由 AI 临时生成。

处理方式为 `保留答案原件 → AI 提取关键步骤 → 用户一次确认`：答案原件负责最终展示，确认后的关键步骤负责 AI 提示和粗判。

录题阶段优先让用户输入或口述自己的思路；用户无法补全时，才由 AI 协助生成候选内容。

答案预处理不能只有一张平铺的步骤清单，题目过程按依赖结构分为两类：

- **线性步骤题**：后续路径不随中间结果改变，可以使用顺序检查点。例如条件全部确定的万有引力题。
- **条件分支题**：需要先得到判别式符号、阈值或其他派生结果，才能决定下一条路径，必须保存“先计算什么、按什么条件分支、各分支继续做什么”。例如数学中的 `Δ > 0`、`Δ = 0`、`Δ < 0`，以及物理中的阈值判断。

### 2.7 复习链路与 AI 边界

第一版复习链路必须接入语音输入和 Q 版 AI 形象。它倾听用户口述、作出表情或动作反馈、判断思路大致是否正确、在需要时揭露提示，并保存本次卡点。

- 复习时展示题目而不展示答案；先让用户主动口述，不先展示标准过程；用户确认结束后再翻页展示标准过程；
- 实时语音转写是第一版 AI 判断链路的**内部输入**。“用户说什么，面板就实时写出什么”的可视化公式面板属于未来展望，不进入第一版；
- 复习不追求每次都完整重做所有细节，时间成本不可接受。AI 负责识别关键步骤和明显错误，用户对最终细节负责；
- AI 可以检查定义域等关键步骤，但完整细节仍由用户人工确认，**AI 不是最终裁决者**；
- 提示内容和提示发生的位置必须保留；
- 对求导后需要继续读取数值、分类讨论等依赖中间结果的题，仅靠口述不够。系统必须允许用户持续看到并处理自己的中间结果；它可以是应用内画板，也可以是用户自己的作答页面，具体承担方式仍待讨论。

“不做 AI 解题助手”特指不做通用搜题和完整解法生成；第一版需要的是**受限的 AI 复习伙伴**。

### 2.8 辨识题与变式题

辨识题使用独立按钮和链路，属于后续独立链路，**初期不实现**。一道题反复复习后仍未掌握，或用户主动要求强化时才进入。

辨识题可以由 AI 生成，也可以在用户明确同意共享后，从相同标签和难度的社区题目中选择。初期先不建立难度星级，后续再根据真实数据设计。

后续辨识题的反馈候选为三档：`不会做 / 有思路但需要提示 / 独立做对`。

辨识题生成、求解和校验保留为后续独立链路，不进入初期 Demo。

### 2.9 图片与存储原则

原始照片与 OCR 衍生结果分开保存。原图不能在未确认时直接丢弃；经用户确认后按公开规则删除原图，并向用户明确展示可用存储空间。

原图保留时间、用户存储额度和自动删除规则仍待确定。

### 2.10 复习调度的第一版边界

第一版只用可解释的 1、3、7、14、30 天规则验证产品，只保存运行当前闭环和解释本轮结果所需的最小记录。

固定间隔和 FSRS 不再作为二选一：FSRS 及其高级信号、迁移字段留到原型验证后的工程化阶段。原型 Demo 暂不引入随机复习时间、复杂作答模式、响应时长优化和 FSRS 高级反馈信号。

### 2.11 第一版明确不做

- 全科 AI 老师、通用搜题或完整解题助手；
- 社区排行榜、公开比较错题数量和他人完整思路展示；
- 学习机等自有硬件；
- 完整个人画像、全局知识图谱和复杂推荐系统（核心闭环验证前不建设）；
- 未经平台许可逆向第三方私有接口或批量抓取题库；
- 在真实需求出现前承诺维护完整自托管产品。

### 2.12 数据主权与 Agent 友好开放

**已确认（2026-08-01，用户明确提出的产品理念）：** 错题局是一个对开发者 Agent 友好的系统。用户拥有自己的数据主权：他的数据、他自己的模型，可以随时方便地进来调用。

具体原则：

- **接口对模型友好**：所有用户数据通过稳定、版本化、机器可读的 API 暴露（OpenAPI 为唯一契约，错误码语义化）；在此之上提供 MCP（Model Context Protocol）适配层，让用户的 Agent 用 URL + 个人令牌即可接入，托管形态（零安装）为主，本地 CLI 形态为辅。
- **授权即主权**：用户不发密码给 Agent，发的是按范围授权的个人访问令牌（读错题 / 读批注 / 读统计等 scope），可随时吊销；每一次 Agent 调用都进审计日志，用户能看到自己的模型动过什么。
- **先读后写**：开放接口第一版只读（错题、批注、复习统计），写入能力在真实场景验证后再开放。
- **能进也能出**：全量导出（结构化数据 + 图片资产）是数据主权的一部分，与 8.8 节"定义并公开自己的导入导出格式"互为表里。
- **边界**：不向 Agent 开放他人数据与社区未公开内容；开放接口不成为绕过复习机制批量导出题库的渠道。

实现时点：理念自今日起为产品定论，指导 API 设计（机器可读优先）；MCP 适配层与导出端点在核心闭环验证后排期，不进入第一版开发范围。

## 3. 进阶功能候选

以下能力由用户提出，但优先级和具体规则尚未全部确认：

1. **题型与标签**：识别高中题目类型并打标签。
2. **整体复习**：通过模板让 AI 对用户已存资料进行整体复习。
3. **考前突击**：立即复习所有已进入复习状态的内容。
4. **标签检索**：按标签寻找题目并进行强化练习。
5. **个人画像**：随数据积累持续更新，预测空白试卷中对用户有价值或可能做错的题目。
6. **照片标记提取**：识别学生在原题上的标记，生成可编辑备注。
7. **批量录入**：一次连续上传多张题目照片。
8. **变式题**：原题优先；多次做错后触发变式。候选阈值为错 3 次。
9. **共创题源**：变式题可由 AI 生成，也可来自同标签下其他用户共享的真实题目。

## 4. 科大讯飞能力与候选架构

用户计划后续接入科大讯飞 API。官方公开能力核查见 [`SRC-20260729-02`](sources/SRC-20260729-02-iflytek-api-capabilities.md)。

### 4.1 星火 X2 与教育行业能力

通用“星火深度推理 X2”已于 2026 年 2 月上线，并提供 HTTP 和 WebSocket API；它支持动态思考模式、较长上下文和 Function Call。科大讯飞另有基于 X2 升级的教育行业模型及批改、学习机等产品能力。

当前需要区分两者：

- 通用 X2 已有公开 API，可作为候选推理底座；
- 教育行业能力已经公开展示，但尚未在公开开发文档中确认一个可直接自助开通、单独命名为“教育 X2 API”的标准接口。

详细核查见 [`SRC-20260729-03`](sources/SRC-20260729-03-spark-x2-and-market-scan.md)。

### 4.2 能力映射

| 错题局模块 | 候选讯飞能力 | 当前判断 |
|---|---|---|
| 印刷题干与数学公式提取 | 公式识别 API | 官方明确覆盖高中印刷题干和公式 |
| 学生手写标记提取 | 手写 OCR / 图片理解 | 需要实测，公开文档未承诺自动区分题干与批注 |
| 题型和知识点标签 | 星火大模型结构化输出 | 需自建标签体系；未找到现成完整标签 API |
| 整体复习和跨题问答 | 星火知识库 / Embedding | 可作为检索能力，不建议作为业务主数据库 |
| 个人画像和错题预测 | 星火大模型辅助分析 | 画像特征和历史数据应由错题局自己保存 |
| 批量离线处理 | 星火批处理或自建任务队列 | 待比较时延、价格和模型覆盖 |

> Agent 架构建议：错题局自建业务数据底座，讯飞作为可替换的 OCR、大模型、图片理解与检索能力供应商。见 [`TRD-0003`](memory/tradeoffs/TRD-0003-iflytek-integration-boundary.md)。

候选数据流：

`原始照片 → OCR 衍生结果 → 用户校对 → 结构化错题卡 → 复习调度 → 作答历史 → 标签与个人画像 → 可选社区共享`

原始照片、OCR 结果和社区共享状态应分开保存。图片黑白化暂不拍板；建议保留原图，再用真实样本比较原图、灰度和二值化的识别质量。

### 4.3 X2、教育专属模型、知识库和 Skill 的关系

教育侧不是单一 Skill，而是一个组合技术栈：

| 层 | 作用 | 错题局中的候选用途 |
|---|---|---|
| 通用或教育专属模型 | 理解、推理和生成 | 标签、错因结构化、复习摘要 |
| 教育数据与专门训练 | 让输出更符合学科和教学场景 | 教学步骤、错因、知识点 |
| 知识库 / RAG | 检索模型外部资料 | 教材、课程标准、个人历史资料 |
| Skill / 工具 | 完成单项外部动作 | 公式 OCR、图片理解、语音 |
| 错题局业务规则 | 管理状态、权限和学习流程 | 复习调度、备注、共享协议 |

科大讯飞确实把图片/PDF OCR、图片理解和语音等称为 Skills，但官方对教育行业模型的描述是“行业数据集 + 专业思维链强化学习 + 教育场景”，不能把教育特化理解为只安装了一个 Skill。

科大讯飞公开材料也没有说明教育模型是单纯“基于学习机做出来的”。更准确的关系是：教育专属模型来自其多年教育数据、教师经验和教学思维链，学习机、智能批改和学校方案都是这个底座的应用场景。

### 4.4 知识库边界

讯飞有独立的星火知识库 API，支持文件上传、OCR、切分、向量化、检索、重排、总结、问答和引用返回。它可以服务“整体复习”和跨题检索，但它不是 X2 的永久记忆，也不能替代错题局自己的业务数据库。

### 4.5 API 价格快照

截至 2026-07-29，讯飞官网展示：

- Spark X2：约 2～3 元/百万 tokens；按量表中 X2/X1.5 为 2 元/百万 tokens；
- Spark X2 Flash：约 1～2 元/百万 tokens；
- X2 Flash 套餐从 1 亿 tokens / 200 元起；
- 教育专属模型没有公开独立标准 API 价；
- OCR、知识库、Embedding、联网搜索和定制服务可能另行计费。

价格会变化，采购时以控制台和合同为准。详细来源与 DeepSeek 价格对照见 [`SRC-20260729-04`](sources/SRC-20260729-04-x2-deepseek-pricing-and-education-stack.md)。

### 4.6 与 DeepSeek 的候选取舍

当前 DeepSeek 官方主模型为 V4，而不是早期 R1。二者对错题局的价值不同：

| 维度 | 星火 X2 / 讯飞体系 | DeepSeek V4 |
|---|---|---|
| 核心优势 | 教育行业资产与 OCR、语音、知识库组合 | 通用推理、开放权重、低成本和 1M 上下文 |
| 教育产品经验 | 学习机、批改、学校和教师产品较完整 | 官方没有同等完整的 K12 产品栈 |
| 配套能力 | 同一供应商可提供公式 OCR、图片、语音和 RAG | 通常需要组合其他服务 |
| 开放性 | API 开放，教育专属能力和模型权重开放度较低 | 官方开放模型权重，自部署和迁移选择更多 |
| 公开价格 | X2 约 2～3 元/百万 tokens | V4 Flash：未命中输入 US$0.14、输出 US$0.28/百万 tokens |
| 适合作用 | 教育能力与一站式供应链候选 | 通用模型基线和低成本对照组 |

> Agent 推断：不能仅根据厂商榜单断言 X2 比 DeepSeek 更适合。建议让讯飞 OCR 独立完成图像识别，再用同一份 OCR 文本同时测试 X2 和 DeepSeek V4 Flash，对比结构化准确率、标签一致性、错因质量、时延和实际成本。

## 5. 市场定位与竞品

公开产品扫描显示，市场中已经存在大量功能相近方案：

- 科大讯飞 AI 学习机、有道智慧教育、作业帮和小猿学练机覆盖错题、学情分析、个性化练习或 AI 辅导；
- MistakeBook、题型宝、AI 错题本、智芽 AI 错题本等更直接覆盖拍照录入、OCR、标签、错题本、间隔复习、相似题或薄弱点分析。

因此，以下单点功能不能单独作为错题局的差异化：拍照 OCR、自动标签、遗忘曲线、数字错题本、变式题和薄弱点分析。

> Agent 推断：值得进一步验证的差异化组合是“回看自己上一次的思考和错因 → 优先复习原题 → 多次失败后才引入变式”，再叠加自愿、互惠的真实题目社区。该表述尚未由用户确认，也没有经过竞品实测和用户研究。

### 5.1 专门错题工具与产品思路

### 5.2 AI 错题本重点拆解

用户认为 AI 错题本整体上非常接近自己想做的产品，但具体 UI 和实现逻辑仍需调整。

其公开会员配置为：

| 计划 | 价格 | 试卷上传/月 | 快速拍照/月 | 合计 AI 录入动作 |
|---|---:|---:|---:|---:|
| 免费版 | 0 元 | 3 | 5 | 8 |
| Premium | 29.9 元/月 | 30 | 30 | 60 |
| VIP | 49.9 元/月 | 50 | 50 | 100 |

Premium 和 VIP 若全部用满，名义收入都约为每次 0.50 元。产品帮助页称付费会员可“无限试卷上传”，但公开会员配置仍设 30/50 次上限，存在明显口径冲突。

### 5.3 为什么录入限制严格

结论：不是单纯因为 OCR 贵，而是它售卖的是一条完整 AI 处理流水线，同时用配额控制重度用户、批量滥用和会员分层。

- 普通 OCR 的公开云价格可以低至约 0.005 元/次；
- 专业“试卷分析与识别”的公开按量价约为 0.16 元/次；
- AI 错题本一次上传最多 2 张图，随后还包括整卷切题、公式/手写、结构化解析、三维标签、多模型复核、重试和存储；
- Agent 暂按每次完整处理 0.25～1.00 元做敏感性估算，并非该产品真实合同成本；
- 如果付费用户把所有额度用满，订阅收入可能不足以覆盖可变成本，因此配额重点是在防少数重度用户拖穿毛利；
- 不限量还会带来整套教辅批量数字化、版权、账号共享、自动脚本和第三方 API 并发风险；
- 把录题入口设为额度，也有明显的会员升级和价格分层目的。

> Agent 判断：它的限制在商业上可以解释，但对学习产品而言偏苛刻。录题是最需要培养的行为，把它过早做成稀缺资源会增加用户每次拍照时的心理成本。帮助页“无限”和后台硬上限不一致，也会损害信任。

详细依据见 [`SRC-20260729-05`](sources/SRC-20260729-05-ai-error-book-quotas-cost-and-open-source.md)。

### 5.4 错题局可采用的候选收费边界

| 层 | 能力 | 候选策略 |
|---|---|---|
| 基础录入 | 保存原图、裁切、手动建卡、手动备注、复习调度 | 免费或非常宽松 |
| 轻量 AI | 普通 OCR、基础标签、批量去重 | 较大月额度 |
| 深度 AI | 整卷结构化、复杂公式/手写、错因诊断、多模型复核 | 消耗点数或明确月额度 |
| 生成和报告 | 变式题、专项训练、知识图谱、长报告 | 独立额度或增值包 |

> Agent 建议：错题局应把成本控制点放在昂贵 AI 动作，而不是“保存一道错题”。这样既能保住核心录入习惯，也能通过按需升级模型、缓存、图片去重和用户校对控制成本。此收费边界尚待用户确认。

### 5.5 开源可用性

有开源项目和组件，但没有发现可直接替代 AI 错题本完整生产流程的现成方案：

- [`wttwins/wrong-notebook`](https://github.com/wttwins/wrong-notebook)：最接近完整错题本，包含 AI 分析、知识点标签、相似题、打印/PDF、统计、多用户和管理端，并支持 OpenAI 兼容 API；商业使用前需核对许可证与代码质量。
- [`PaddleOCR`](https://github.com/PaddlePaddle/PaddleOCR)、[`OpenOCR`](https://github.com/Topdu/OpenOCR)、[`MonkeyOCR`](https://github.com/Yuliang-Liu/MonkeyOCR)：可作为 OCR、公式、表格和文档解析底座。
- [`Umi-OCR`](https://github.com/hiroi-sora/Umi-OCR) 和 [`Surya`](https://github.com/datalab-to/surya)：可用于离线 OCR、版面和 LaTeX 识别。
- [`PageLM`](https://github.com/CaviraOSS/PageLM)：可参考学习材料转卡片、测验和间隔复习的流程。

开源能降低软件授权费和供应商锁定，但 GPU/服务器、存储、模型推理、运维和合规成本依然存在。

### 5.6 与教育巨头竞争的现实边界

科大讯飞和作业帮已经拥有上线多年的 App、学习硬件、内容、题库、教研和渠道，不能与早期独立产品“AI 错题本”视作同一种竞争者。

> Agent 判断：如果错题局要正面竞争全科 AI 老师、海量题库、视频讲题、个性化推荐和硬件闭环，资源差距大到没有战略意义。硬件巨头不是因为每项功能都完美才危险，而是它们能够把一个“不够好但够完整”的功能预装进已经售出的设备。

另一方面，硬件购买重、系统封闭、功能复杂，也未必解决用户把不同来源错题汇总后进行长期自我复盘的问题。错题局仍可能占据更窄的位置：

`手机上的跨来源错题收件箱 → 保存自己的错误思路 → 原题优先复习 → 失败后才调用变式`

详细依据见 [`SRC-20260729-07`](sources/SRC-20260729-07-incumbent-maturity-and-data-portability.md)。

## 7. 当前风险与未知

- 高中题目标签的准确率和标签体系尚未验证。
- 手写标记与印刷题干能否稳定分离尚未验证。
- 社区题目存在隐私、版权、撤回和内容治理问题。
- 面向未成年人使用讯飞 API 时，需要完成告知、同意和相应监护人授权设计。
- 个人画像和“预测容易错的题目”需要足够数据，不能在冷启动阶段假定有效。
- “AI 错题本 + 记忆曲线”的功能组合已有较多同类产品，差异化尚未验证。
- 展会展示的教育能力不等于已开放、可采购且有稳定 SLA 的开发接口。

## 7.1 创始人现场优势

创始人本人就是在校高中生，长期处在真实的高中学习、考试和复盘环境中。这些经历可以转化为“创始人即目标用户”、快速同学反馈、公开构建和技术社区连接，但不能替代产品质量、隐私合规和持续执行。

> Agent 推断：与 AI 错题本竞争时，最难复制的不是某个 OCR 或大模型 API，而是高中生日常现场的高频反馈循环，以及对“什么时候愿意录题、为什么不愿复盘、考前怎样临时改变行为”的具体理解。

## 7.2 未来约 12 个月的成功定义

用户已确认：

`个人声誉与下一阶段机会 > 真实高中生使用与自身学习；收入守住不长期亏损底线`

真实用户不是装饰性注册量，而是声誉的可信证据。优先指标应是持续使用、复习完成、错题减少和可公开复盘的产品改进，而不是先追求大规模下载。相关决策见 [`DEC-0013`](memory/decisions/DEC-0013-reputation-first-with-users-and-cost-floor.md)。

### 五个案例的真实情况

| 项目 | 开放边界与收费方式 | 真正证明了什么 | 对错题局的限制 |
|---|---|---|---|
| Supabase | 主仓库 Apache-2.0，可自托管；官方云销售数据库运维、备份、可靠性和平台能力 | 宽松许可证下，品牌、速度和托管能力也能形成大公司；2026 年融资 5 亿美元、投前估值 100 亿美元 | 面向开发者；融资和估值不等于盈利 |
| PostHog | 大部分 MIT，部分企业功能另行许可；商业重心是 Cloud | 开源帮助获得早期用户、口碑和人才；自托管支持成本最终推动其转向云服务 | 面向技术团队；学生不会因为 MIT 而使用产品 |
| Moodle | LMS 核心 GPL；MoodleCloud、实施、培训、托管与认证服务商收费 | 教育开源可建立二十多年生态；2025 年注册站点超过 5 亿用户 | 购买者主要是学校和机构，不是高中生个人 |
| Appwrite | 主仓库 BSD-3-Clause，可自托管；官方 Cloud 收费 | 宽松开源能支持开发者社区、招聘、融资和云业务 | stars、融资和开发者数不是盈利证明 |
| Cal.com / Cal.diy | 2022 年为 AGPL open core；2026 年生产版转闭源，只保留 MIT 的 Cal.diy | 开源可形成品牌和分发，也可能因维护、商业或安全压力改路 | 已不应被描述为当前完整生产版开源案例 |

因此，已有案例证明“开源可以服务于分发、信任、招聘和声誉，官方托管可以收费”，但没有证明“高中生错题 App 一开源就会获得学生和利润”。最接近教育行业的 Moodle 仍是机构市场案例。

### To C 为什么不同

| 维度 | To B | To C |
|---|---|---|
| 开源的直接价值 | 私有化、合规审计、定制、避免供应商锁定 | 对少数技术/隐私用户重要；普通用户主要关心体验和结果 |
| 自托管价值 | 企业可能有专职团队，价值较高 | 普通消费者不愿配置服务器，价值很低 |
| 付费理由 | SLA、运维、集成、权限、支持 | 省事、移动体验、同步、备份、AI 额度和内容 |
| 传播对象 | 使用者、技术决策者和付费者可能重合 | 开源传播者、学生使用者和家长付费者可能是三群人 |
| 商业风险 | 支持和企业交付成本高 | 客单价低、转化敏感，免费版本容易成为价格锚点 |

To C 并非没有成功样本，但成功者通常更接近 prosumer：

- **Anki：**免费开源电脑端，官方 iOS App 闭源并一次性付费；销售收入支持整个项目。它与错题局的选择性开源路线最接近，但 Anki 的本地调度几乎没有持续 OCR/模型成本，错题局不能照搬“一次付费、永久免费服务”。
- **Joplin：**桌面和移动应用采用 AGPL，用户可以选择自己的同步服务，也可以购买官方 Joplin Cloud；这是“C 端应用本身开源 + 官方云收费”的直接案例。
- **Home Assistant：**核心开放，消费者可为免配置的官方云便利付费；用户大量是智能家居和技术爱好者。
- **Bitwarden：**个人免费基础层、Premium/Family 订阅和自托管并存；证明开源不等于全部高级服务免费。

错题局存在三个不同角色：

1. 高中生因为拍照快、复习负担低、能减少重复错误而使用；
2. 学生本人或家长因为效果、可靠性、数据安全和成本可控而付费；
3. 开发者、导师、比赛评委和教育技术研究者因为协议、状态机、评测和真实数据证据而关注开源项目。

不能指望“开源”同时完成三项任务。面向学生时，开源应翻译成“数据可导出、不会被锁定、基础复习长期可用”，而不是把许可证名称当卖点。

### To C 条件下对开源路线的修正

不建议第一天就承诺维护完整自托管产品。它对高中生几乎没有购买价值，却会产生安装、升级、安全和免费支持成本。

更合理的候选顺序：

1. 开放错题数据格式、复习状态机、导入导出、模型适配和评测工具；
2. 官方 App 是唯一重点打磨的学生端；
3. 免费基础复习不能用过低录题配额破坏习惯；
4. 对云同步、备份、批量处理、OCR/AI 额度和社区能力收费；
5. 完整自托管等出现真实学校、开发者或隐私用户需求后再提供。

Agent 当前建议把两种 To C 模式结合：**开放方法层 + 官方消费应用**，同时采用**免费基础复习 + 付费云与 AI**。开源服务于技术声誉、互操作和长期信任；消费者收入来自便利、效果和持续成本。该建议仍待用户确认。

详细 To C 样本与分析见 [`SRC-20260729-09`](sources/SRC-20260729-09-consumer-open-source-models.md)。

开源边界候选：

- 可开放：错题卡数据格式、复习调度引擎、OCR/模型适配接口、导入导出和评测工具；基础自托管版本等真实需求出现后再决定；
- 不开放或另行决策：用户照片、个人画像、私有错题、社区数据、密钥、运营风控和可能构成数据飞轮的资产；
- 官方付费价值：稳定托管、多端同步、备份、推送、模型额度、低延迟、社区题库和无需配置的移动体验。

详细取舍见 [`TRD-0004`](memory/tradeoffs/TRD-0004-open-source-core-paid-hosted-app.md)，案例来源见 [`SRC-20260729-06`](sources/SRC-20260729-06-open-core-hosted-service-cases.md)。

基于用户已确认的“声誉优先、真实用户为证据、收入守住成本”排序，Agent 当前推荐选择性开源：

- 开源真正体现方法论的错题卡格式、调度引擎、模型适配、导入导出和评测工具；
- 官方应用保留账号、同步、推送、备份、计费、风控、社区和移动端体验；
- 通过托管订阅和预付 AI 点数覆盖服务器及模型成本；
- 不开放真实用户数据、社区非公开数据、密钥或运营风控。

该方案已记录为候选 [`DEC-0014`](memory/decisions/DEC-0014-selective-open-core-hosted-app.md)，尚待用户确认。

### 许可证：宽松与严格到底差在哪

“严格”不是指禁止赚钱，而是指别人拿走代码以后必须承担多少回馈义务。真正的开源许可证必须允许商业使用；如果条款直接禁止竞争性托管或生产使用，通常属于“源码可见”，不能等同于 OSI 开源。

假设别人拿走错题局引擎，修改后做成收费网站：

| 许可证 | 对方能收费吗 | 对方要开放什么 | 适合错题局的部分 |
|---|---:|---|---|
| MIT / BSD-3-Clause | 能 | 通常只保留版权和许可声明，修改可闭源 | 追求最大传播的简单工具 |
| Apache-2.0 | 能 | 与 MIT 接近，并有更明确的专利授权、NOTICE 和商标边界 | 数据格式、SDK、导入导出、评测工具 |
| MPL-2.0 | 能 | 修改过的 MPL 文件继续开放，其他文件可闭源 | 希望保住核心文件但方便嵌入的中间路线 |
| GPL-3.0 | 能 | 向外分发衍生软件时通常需提供源码；纯 SaaS 通常不触发 | 桌面或可分发程序，不是防 SaaS 私改的最佳选择 |
| AGPL-3.0 | 能 | 修改后通过网络提供服务时，也需向网络用户提供对应源码 | 服务端复习与错因工作流引擎 |
| BSL / SSPL 等 | 依条款 | 可限制生产使用、竞争性托管或要求开放更大服务栈 | 商业控制更强，但不属于纯粹开源，现阶段不建议 |

#### Apache、GPL、AGPL 和 HPL 的直观区别

- **Apache-2.0：**别人可以直接复用、修改、闭源和收费，主要义务是保留许可、归属和修改说明；它有明确专利授权。适合希望成为公共接口的 SDK、数据格式和适配器。常用名称是 Apache-2.0，不是“Apache 1.20”。
- **GPL-3.0：**别人分发修改后的衍生程序时，通常必须向接收者提供对应源码；只在自己服务器运行通常不因网络访问而触发。
- **AGPL-3.0：**在 GPL 基础上增加网络交互条款，修改后作为 Web 服务提供时也需要向网络用户提供对应源码。
- **HPL：**如果指 Honest Public License，它是 2006 年为堵 GPL 网络服务漏洞而产生的历史许可证；原推动者 Funambol 随后转向兼容性和标准化更好的 AGPLv3。错题局没有理由使用 HPL。

### AI Coding 时代，开源与闭源是否无所谓

不无所谓，但代码保密的价值确实下降了。

AI/Vibe Coding 削弱了普通功能清单、CRUD 页面和标准架构的防御力。即使错题局闭源，别人仍然可以看着功能重新实现。因此，闭源不能作为主要护城河。

但开源仍然会改变：

- 对方是参考功能重写，还是可以直接 fork 和兼容；
- 对方是否必须遵守 Apache 的归属要求或 AGPL 的源码回馈义务；
- 错题局能否形成可验证的公开作品、贡献记录和技术声誉；
- 数据格式和 SDK 是否更容易成为外部软件的接入标准；
- 用户是否拥有退出权和长期信任。

闭源仍能延缓逐行复制，保护运营后台、风控、未公开实验和快速试错空间，并减少公共兼容和自托管支持负担。

真正难复制的部分不再是普通代码，而是：

- 学生长期复习历史和真实使用习惯；
- 经真实题目验证的错因结构与评测体系；
- OCR/模型路由的质量、稳定性和成本控制；
- 社区题目权利、审核与网络效应；
- 用户分发、品牌、信任和持续迭代速度。

因此，许可证决定的不是“别人能不能做出相似产品”，而是“别人能否直接拿走实现、是否必须回馈，以及用户能否把它视为一个公开可信的项目”。详细分析见 [`SRC-20260729-10`](sources/SRC-20260729-10-apache-gpl-hpl-and-ai-copyability.md)。

许可证还不能替代以下边界：

- 用户照片、个人画像、私有错题、密钥和社区题库不会因代码开源而自动开放；
- 软件许可证不授予“错题局”品牌使用权；
- 已经按开源许可证发布的旧版本不能被单方面收回；
- 外部贡献者也拥有其贡献的版权。若未来想改许可证，需要事先设置贡献规则或 CLA；CLA 会增加商业灵活性，也可能降低社区信任。

### 哪些宽松许可证项目可以直接集成

“可以集成”必须落到具体仓库、具体目录和具体版本，不能仅凭产品名称判断。

| 项目 | 许可证边界 | 可能的参考或集成价值 | 特别注意 |
|---|---|---|---|
| Ghost | 主项目 MIT | 完整消费软件、开源项目与官方托管并存的案例 | 代码许可不包含 Ghost 品牌和 Ghost(Pro) 服务 |
| Excalidraw | 应用及可嵌入包 MIT | 题目画布、圈画和批注交互 | 保留许可，品牌与素材另查 |
| Appwrite | 主仓库 BSD-3-Clause | 认证、存储和后端能力 | 不得用原作者或贡献者名称为产品背书 |
| PostHog | 主仓库大部分 MIT，`ee` 等目录另行许可 | 事件分析与产品数据 | 不能把整个仓库笼统当作 MIT |
| Supabase | `supabase/supabase` Apache-2.0 | 自托管后端和平台架构 | 组织内其他仓库许可证可能不同 |
| Home Assistant Core | Apache-2.0 | 宽松核心加官方云便利的 To C 案例 | 前端、App、插件和品牌另查 |
| Tesseract OCR | Apache-2.0 | 印刷文字 OCR | 依赖和语言数据另查 |
| PaddleOCR | 主仓库 Apache-2.0 | 中文、版面和公式 OCR 候选 | 模型权重、训练集、字体与素材可能另有条款 |

MIT、BSD 和 Apache-2.0通常都允许复制、修改、商业集成和闭源分发；这不代表“随便复制”。每个引入项至少记录上游 URL、commit、复制文件、许可证、NOTICE、依赖与资产许可证、修改情况，并维护 `THIRD_PARTY_NOTICES`。开源代码许可不会自动授予 API、模型权重、训练数据、题库、Logo 或产品名。

Apache-2.0比 MIT/BSD 多一些 NOTICE、修改说明和专利条款，但明确专利授权通常更适合商业 SDK、协议和基础组件。详细清单见 [`SRC-20260729-11`](sources/SRC-20260729-11-permissive-products-and-pr-governance.md)。

### 开放核心与收费版如何处理外部 PR

必须先区分三种机制：

| 机制 | 贡献者做出的声明或授权 | 是否给项目方额外重新许可权 | 当前适用性 |
|---|---|---:|---|
| DCO | 我创作了代码或有权提交 | 否 | Apache-2.0开放方法层的当前首选 |
| CLA | 保留版权，但授予项目方合同约定的广泛权利 | 可以有 | 仅在双重许可或未来改许可确有需求时采用 |
| 版权转让 | 把贡献版权转给项目方 | 是 | 控制最强、信任成本最高，当前不建议 |

PR 的公开边界应提前写死：

1. PR 提交到开放仓库并被合并，新功能就继续进入开放版本；
2. 官方收费版可以部署和使用它，因为收费来自托管、同步、AI 额度、运营和服务，不是买断贡献者成果；
3. 只准备放入闭源商业版的功能，不接收普通志愿者 PR；应由项目方自研、付费委托，或在提交前签订透明的商业协议；
4. 新功能先走 Issue/RFC，再检查来源、许可证、测试、文档和维护成本；
5. 即使技术正确，偏离路线或长期维护成本过高的 PR 也应拒绝。

对错题局的 Agent 当前建议是：

- Apache-2.0的格式、SDK、评测和复习状态机使用同许可证进入加 DCO；
- 官方 App 的账号、支付、社区、风控和生产运维保留在独立私有仓库；
- 如果 AGPL 引擎始终按 AGPL 发布，官方只是合规托管并开放相应修改，不必仅因收费而取得重新许可权；
- 只有要把同一份 GPL/AGPL 贡献放进闭源商业引擎时，才需要在贡献发生前采用经专业审核的 CLA。

最坏的治理方式是：用“共同建设”吸收志愿者的新功能，再悄悄把它锁进收费版。这在法律上或许能通过一份极宽 CLA 实现，但会直接毁掉开源声誉。详细取舍见 [`TRD-0005`](memory/tradeoffs/TRD-0005-contributor-rights-and-commercial-edition.md)。

### 三套候选组合

1. **最大传播 L：**格式、SDK、评测和引擎全部 Apache-2.0，官方应用闭源。最易接入，也最容易被闭源复制。
2. **互惠平衡 R（Agent 当前建议）：**格式、导入导出 SDK、评测工具使用 Apache-2.0；服务端复习与错因工作流引擎使用 AGPL-3.0；官方移动端、账户、同步、计费、社区、风控和生产运维闭源；自托管者自带模型密钥。
3. **商业保护 P：**格式和 SDK 使用 Apache-2.0；核心服务端使用 BSL 或自定义源码可见许可；官方应用闭源。控制更强，但开源声誉更弱且法律解释成本更高。

这里最尖锐的判断是：如果错题局公开的只是普通 CRUD App，它几乎不会给用户带来想要的名声。值得公开的必须是别人可以独立理解、验证和引用的方法论资产，例如错题数据协议、复习状态机、错因结构、跨软件导入适配和评测基准。

详细案例、许可证来源与推理见 [`SRC-20260729-08`](sources/SRC-20260729-08-open-source-cases-and-licenses.md)。

### 8.8 数据可迁移与跨软件接入

用户希望错题局能接入其他学习软件，例如导入作业帮中的个人错题。当前公开资料中未找到作业帮面向第三方的个人错题 API，因此不能把直接 API 同步作为确定前提。

候选接入顺序：

1. 错题局定义并公开自己的 JSON/ZIP 导入导出格式；
2. 支持用户主动导入照片、截图、PDF 和 Word；
3. 提供 iOS/Android 系统分享入口，让用户从其他 App 主动发送到错题局；
4. 如第三方未来提供正式 API/OAuth，再做授权同步；
5. 不以模拟登录、逆向私有接口或批量抓取题库作为产品基础。

这里必须区分“迁移用户自己的作答、备注和复习记录”与“复制第三方题库、答案和解析”。后者涉及版权、平台条款和社区再分发风险。

## 9. 隐性知识采集方式

用户可以用口述转文字、零散消息或照片持续输入，不需要先整理。每轮采用以下结构：

1. 保存用户的原始表达和来源；
2. 区分事实、经历、直觉、假设、需求和决定；
3. 由 Agent 复述其理解，并明确标注推断；
4. 每次只追问一个关键问题；
5. 把未确认内容保留为候选；
6. 只有用户明确说“确认、采用、拍板”或同等意思后，才升级为当前真相。
